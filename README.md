# MAX Chat — GREEN-API

Тестовое задание: интерфейс отправки и получения текстовых сообщений MAX
на React + TypeScript.

**Текущий этап:** отправка и получение текстовых сообщений. Доступны подключение
GREEN-API, создание чата по номеру и переписка в светлой и тёмной темах.

## Локальный запуск

Требуется Node.js 22.18+ в ветке 22 либо Node.js 24+ и npm.

```sh
npm ci
npm run dev
```

Откройте адрес из терминала (обычно http://localhost:5173).
Файл `.env` не нужен. Учётные данные вводятся в интерфейсе.

## Технологии и структура

Проект создан командой `npm create vite@latest . -- --template react-ts --no-interactive`.
React, TypeScript, Vite, Axios. Стили — Tailwind CSS через
[официальный Vite-плагин](https://tailwindcss.com/docs/installation/using-vite).
ESLint и Prettier настроены отдельно. Используется один `tsconfig.json`.

```text
src/
  app/                  # Сборка приложения и глобальные стили
  pages/ChatPage/        # Страница чата
  pages/ConnectPage/     # Страница подключения
  widgets/chat-sidebar/ # Боковая панель чатов
  widgets/conversation/ # Область переписки
  features/             # Подключение, создание чата, отправка и тема
  entities/chat/        # Типы и стор чатов
  entities/message/     # Типы, стор сообщений и пузырёк сообщения
  shared/configs/       # Настройки Axios
  main.tsx              # Точка входа
```

Архитектура — FSD по мотивам
[frontend-nutrition](https://github.com/AndreyTorkhov/frontend-nutrition).
Запрос и логика подключения находятся в `features/connect-account`.
Учётные данные хранятся в состоянии `App`. Список чатов, выбранный чат и действия
над ними — в Zustand-сторе `entities/chat/store.ts`, по подходу из референса.
Сообщения и черновики по чатам — в `entities/message/store.ts`.
Выход очищает оба стора. Форма подключения использует React Hook Form.
Для nullable-типов используется `TMaybe<T>`.

Компонент находится в `index.tsx` внутри своей папки, без вложенной `ui`
и файлов реэкспорта. Типы (`interfaces.ts`), состояние (`store.ts`) и хуки
добавляются по мере необходимости. Каждый хук находится в `hooks/useName.ts`,
каждый хелпер — в `helpers/helperName.ts`. Правила полей вынесены в `validation.ts`.
Если свойств два и более, компонент принимает `props`, хелпер или хук — `params`;
деструктуризация выполняется внутри тела функции.
Собственные интерфейсы имеют префикс `I`, типы — `T`.
Скачанные компоненты `shared/ui` сохраняют исходный стиль библиотеки;
меняем их только для доработки логики или визуала.

## Компоненты интерфейса

[shadcn/ui](https://ui.shadcn.com/docs/installation/vite) настроен через
`components.json`: стиль `default`, база `zinc`, CSS-переменные и иконки Lucide,
как в референсе. Светлая и тёмная палитры MAX заданы в `src/app/styles/index.css`.
По умолчанию используется светлая тема. Кнопка рядом с заголовком «Чаты»
переключает тему; выбор сохраняется в localStorage. Провайдер и хук находятся
в `shared/configs/theme`, по подходу из референса.

В `shared/ui` добавлены Button, Input, Textarea, Label, Card, Dialog, Avatar,
ScrollArea, Separator, Skeleton, Alert и Tooltip. Компоненты редактируем локально.
Для объединения Tailwind-классов используем базовый `cn` из `shared/lib/utils.ts`.
В `components.json` сохранён алиас `utils`, отдельно добавлен `helpers` →
`@/shared/helpers`, аналогично `hooks` → `@/shared/hooks`.
Общий `FormField` объединяет поле ввода, подпись, подсказку и ошибку.
Аватар чата переиспользуется в списке и заголовке переписки.

Jest настроен только для хелперов в Node. Тесты находятся рядом с хелпером:
`features/create-chat/helpers/normalizePhoneNumber.test.ts`.

Новый компонент можно загрузить командой `npx shadcn@latest add <имя>`.
После генерации переносим `<имя>.tsx` в `<имя>/index.tsx`, а собственные интерфейсы
и варианты выносим в соседние файлы. Существующие компоненты не перезаписываем
без проверки локальных изменений.

## Подключение GREEN-API

1. Создайте аккаунт в [кабинете GREEN-API](https://console.green-api.com/)
   и инстанс для **MAX**. Отдельный бот для этого сценария не требуется.
2. Авторизуйте инстанс по QR-коду в кабинете. В MAX откройте
   «Профиль → Устройства → Войти по QR-коду». Актуальные условия авторизации
   приведены в [инструкции сервиса](https://green-api.com/v3/docs/before-start/).
3. Скопируйте `idInstance`, `apiTokenInstance` и `apiUrl` из настроек инстанса
   в форму приложения. `https://3100.api.green-api.com` — начальный адрес;
   если кабинет показывает другой, замените его.
4. Нажмите «Подключить». Приложение вызывает
   [GetStateInstance](https://green-api.com/v3/docs/api/account/GetStateInstance/)
   и открывает чат только при состоянии `authorized`.

Если инстанс не готов к работе, форма предлагает проверить его в кабинете.
При ошибке запроса показывает сообщение о неудачном подключении.
Повторная попытка — кнопкой подключения.

Учётные данные хранятся только в памяти вкладки. Выход и перезагрузка удаляют
сессию; выход не вызывает Logout GREEN-API и не отвязывает MAX от инстанса.
Токен не выводится в сообщениях об ошибке. По протоколу GREEN-API токен входит
в URL запроса и виден владельцу браузера в Network.

Запросы идут прямо в GREEN-API без прокси. OPTIONS-проверка адреса `3100` подтвердила
CORS для GET; реальное подключение нужно проверить со своим инстансом.

## Ручная проверка

1. Запустить `npm run check`.
2. Запустить `npm run dev`.
3. Проверить форму подключения. Переключить тему и перезагрузить страницу:
   выбранная тема должна сохраниться. Проверить кнопку с клавиатуры (Tab, Enter).
4. Проверить пустые поля, неверный idInstance и адрес API: запрос не отправляется.
5. Проверить неверный токен и отключённый интернет: появляется ошибка,
   данные остаются в форме, можно повторить попытку.
6. Подключить авторизованный инстанс: появляется экран чата со статусом подключения.
7. Нажать «Выйти»: форма пустая, инстанс в кабинете остаётся авторизованным.
8. Повторить вход и обновить страницу: снова появляется форма подключения.
9. Проверить оба экрана при ширине 375 px и отсутствие ошибок в консоли.

## Создание чатов

После подключения нажмите «+», введите номер получателя с кодом страны и нажмите
«Открыть чат». Пробелы, скобки, дефисы и знак «+» убираются перед запросом.
Номер должен содержать от 7 до 15 цифр. Вводите международный код страны,
например `+7`, а не местный префикс `8`.

Приложение вызывает [CheckAccount](https://green-api.com/v3/docs/api/service/CheckAccount/)
и сохраняет полученный `chatId`. Он нужен для сопоставления отправки и входящих
сообщений. Доступность поиска номера зависит от настроек MAX у получателя.
Новый чат добавляется только после успешного ответа сервиса.

Для ревью этапа 3:

1. Открыть чат с существующим аккаунтом MAX — номер появится в списке и заголовке.
2. Повторно ввести тот же номер в другом формате — откроется существующий чат.
3. Добавить второго получателя, переключиться между чатами.
4. Ввести пустой номер, буквы или слишком короткий номер — запрос не отправится.
5. Проверить ошибку сети и ненайденного аккаунта, затем повторить попытку.
6. Закрыть диалог во время проверки — запрос отменяется, чат не добавляется.
7. На ширине 375 px открыть чат, вернуться стрелкой к списку, проверить обе темы.

Чаты хранятся в памяти и очищаются при выходе или перезагрузке.

## Отправка сообщений

Введите текст и нажмите кнопку отправки или Enter. Shift+Enter добавляет перенос
строки. Пустые сообщения не отправляются, предел — 4000 символов.
Во время запроса повторная отправка и редактирование заблокированы.
При ошибке текст остаётся в поле; автоматического повтора нет.

После успешного ответа SendMessage сообщение появляется в переписке и превью
списка чатов. Пометка «В очереди» означает, что GREEN-API принял запрос;
доставка и прочтение на этом этапе не отслеживаются.
Черновики сохраняются отдельно для каждого чата. Сообщения и черновики хранятся
только в памяти вкладки и очищаются при выходе или перезагрузке.

Для ревью этапа 4 со своим инстансом:

1. Отправить текст второму аккаунту и проверить его получение в MAX.
2. Проверить Enter, Shift+Enter, многострочный текст и эмодзи.
3. Проверить пустой ввод, пробелы и ограничение в 4000 символов.
4. Быстро нажать отправку несколько раз — выполняется один запрос.
5. Отключить сеть в DevTools и отправить текст: появляется ошибка, черновик остаётся.
6. Создать черновики в двух чатах и переключаться между ними.
7. При замедленной сети переключить чат во время отправки: сообщение добавится
   в исходный чат. Выйти во время запроса — данные очищаются.
8. Проверить длинный текст и прокрутку в обеих темах, в том числе на ширине 375 px.

Если ответ сервера потерялся, сообщение могло уже попасть в очередь: перед ручным
повтором проверьте MAX.

## Получение сообщений

В кабинете GREEN-API откройте настройки своего инстанса:

1. Включите «Получать уведомления о входящих сообщениях и файлах» (`incomingWebhook: yes`).
2. Оставьте адрес Webhook (`webhookUrl`) пустым и сохраните изменения.
3. Подождите около минуты перед проверкой.

Основание: [настройка HTTP API](https://green-api.com/v3/docs/api/receiving/technology-http-api/).
Отдельный бот для этого сценария не нужен.

После подключения приложение последовательно вызывает ReceiveNotification и
DeleteNotification. Ожидание уведомления — до 30 секунд, таймаут HTTP-запроса —
35 секунд. Между циклами — пауза 1 секунда, после ошибки — 5 секунд.
При выходе активный запрос и таймер отменяются. В StrictMode повторный запуск
эффекта не оставляет работающий предыдущий цикл.

Отображается текст личных сообщений, включая текст со ссылками. Сообщение
сопоставляется с созданным чатом по `chatId`. Если чат ещё не создан, сообщение
остаётся в памяти и будет видно после открытия чата по номеру в этой же сессии.
Файлы, группы и служебные события не отображаются; их уведомления удаляются,
чтобы очередь продолжала обрабатываться. Повтор одного `idMessage` в том же
чате не создаёт дубль. История из MAX не загружается; после обновления страницы
уже обработанные сообщения не восстанавливаются.

Для ревью этапа 5:

1. Открыть приложение в одной вкладке, подключиться и создать чат с получателем.
2. Отправить сообщение, ответить из MAX: ответ появится слева, превью обновится.
3. Проверить многострочный ответ, эмодзи и текст со ссылкой.
4. Переключить чат и получить ответ в предыдущем: он останется в нужном чате.
5. Прислать изображение, затем текст: изображение пропускается, текст приходит.
6. Отключить сеть: появляется сообщение об ошибке. Включить сеть: получение
   возобновится автоматически.
7. В DevTools заблокировать запрос DeleteNotification: сообщение не должно
   дублироваться при повторных опросах. Снять блокировку — очередь продолжит работу.
8. Выйти во время ожидания: запрос отменяется, новые опросы не запускаются.

На время проверки не запускайте другое приложение или вторую вкладку,
читающую очередь того же инстанса: потребители будут забирать уведомления друг у друга.
